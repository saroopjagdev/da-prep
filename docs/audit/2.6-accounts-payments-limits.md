# 2.6 Accounts, payments and limits: audit

Date: 2 October 2026. Code read (`components/AuthProvider.tsx`, `app/login`, `app/api/account`, `app/api/stripe/*`, `lib/server/{auth,guard,usage}.ts`, `supabase/migrations/*`, `app/pricing`); pages rendered.

**Not tested end to end:** sign-up, login, Stripe checkout, webhook, portal, cancel, failed payment, refund. This environment has no Supabase project, no Stripe test keys, and can't reach Stripe or Supabase. Existing unit tests (`tests/stripe.test.ts`, `usage.test.ts`, `guard.test.ts`) cover the server logic with fakes. The README and launch checklist say the same: Stripe "has never run against Stripe".

## Accounts
| Item | Status |
|---|---|
| Sign up / log in | Email and password with email confirmation (Supabase Auth holds a salted hash; minimum 8 characters) and **password reset by email**; an emailed sign-in link remains as a fallback, and Google when enabled |
| Log out | Present on `/login` |
| Delete account | `DELETE /api/account`: cancels any Stripe subscription first (refuses to delete if cancelling fails), deletes `user_data`, `usage`, `ai_usage`, then the auth user. Good order |
| Data export | "Download backup" (JSON) and restore on `/login` for data stored in the browser (which is also what syncs to the account). No server-side export of the `profiles`/usage rows (minor) |
| Without accounts configured | Everything works locally and the page says so plainly |
| Magic-link email limits | Supabase's built-in sender allows ~2 emails/hour for the whole project: **must have an SMTP provider before launch** (already in the checklist) |

## Limits (server-side enforcement)
| Check | Finding | Severity |
|---|---|---|
| Free limits enforced on the server? | Yes, via Postgres functions `consume_interview` / `consume_review` (service role only; users can't call them) when `ENFORCE_LIMITS=true` | Positive |
| Pro bypass? | Plan stored in `profiles`, which users can read but **not** write (RLS: select-only). Only the webhook (service role) changes it | Positive |
| **Free-limit bypass** | Interview allowance charged only when `history` is empty; a client can send a fake first turn. `/api/interview/score`, `/api/star` and `/api/transcribe` are never counted against the free allowance. Mock processes charge only when the client says `first: true` | **High** |
| Cost ceiling | 150 AI calls/user/day for everyone; ≈ £12/day worst case per account. No per-day cost budget; multiple free accounts multiply it | High |
| Rate limiting | Per-minute limits per route; uses Upstash Redis when configured, otherwise in-memory (per server instance) | Medium until Upstash is set |
| "Unlimited" on the pricing page | Pro says "unlimited" but there is a 150-calls-a-day cap: should say "fair use" (consumer-law risk) | Medium |

## Payments (code review)
| # | Finding | Severity |
|---|---|---|
| 1 | Webhook verifies Stripe's signature; returns 500 on database errors so Stripe retries | Positive |
| 2 | Checkout refuses if already Pro; reuses the Stripe customer | Positive |
| 3 | `checkout.session.completed` sets Pro without checking `payment_status` (fine for cards; wrong for delayed methods) | Low |
| 4 | Events can arrive out of order (e.g. `subscription.updated` before `checkout.session.completed` stores the customer id → update hits no rows). Using the subscription's `metadata.user_id` (already set) would make it robust | Medium |
| 5 | Double-click / two tabs can create two checkout sessions → two subscriptions | Low-Medium |
| 6 | Refunds are not handled in code (a refund doesn't remove Pro unless the subscription is cancelled in Stripe) | Low (process: refund + cancel together) |
| 7 | No adult/parent confirmation at checkout; no record of consent to start digital content immediately (affects the 14-day cancellation right); no price, renewal or cancellation info shown before checkout | **High (legal, see 2.9)** |
| 8 | Pricing page shows **no price** (`NEXT_PUBLIC_PRO_PRICE_LABEL` unset) | Launch blocker (decision) |

## Is Pro worth paying for?
Pro only unlocks more AI interviews and reviews. Tests, tracker and profiles are free. Against Intervyo (£139/season with firm packs, HireVue banks, tests) or Trackr (£30/season for alerts), Pro today is thin. Suggested Pro value (for your decision): firm-specific HireVue presets and investment-bank mocks, larger rotating test banks, Cappfinity/job-simulation tests, deadline alerts, unlimited fair-use AI.

## Score: **5 / 10**
Reasons: the account and deletion design is careful and the plan can't be self-upgraded, but there's a free-limit bypass, no price, consumer-law gaps at checkout, thin Pro value, and nothing has run against real Supabase/Stripe.

## To reach 9+
1. Server-side session tracking for interviews (issue an interview id when the free allowance is charged; require it for next/score/transcribe), count STAR/score against limits, per-user daily cost budget.
2. Webhook: use `metadata.user_id`, check payment status, handle ordering; prevent double subscriptions.
3. Checkout: price shown; renewal/cancellation terms; payer confirms 18+; consent to immediate start; receipts.
4. "Fair use" wording instead of "unlimited".
5. Run the full Stripe test-mode journey once keys exist (Phase 4 E2E).
